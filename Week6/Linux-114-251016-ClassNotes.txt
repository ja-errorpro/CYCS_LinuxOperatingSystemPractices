                           Why shell scripts?                         # by Copilot

Shell scripts are essential because they :

  Automate repetitive tasks : 
    Like backups, software installation, log rotation, or system monitoring.

  Glue together system utilities (e.g., grep, awk, sed, find, curl) : 
    Shell scripts orchestrate these tools to perform complex workflows.

  Support system boot and configuration : 
    Many Linux startup processes and configuration files are shell scripts 
    (e.g., /etc/init.d/* and systemd service scripts).    # will talk about this in this class

Shell scripts typically :

  Run sequences of commands (ls, cd, rm, ...)

  Handle files and directories (copy, move, delete, compress)

  Parse and transform text (grep, awk, sed)

  Monitor system status (CPU, memory, disk usage)

  Schedule tasks (via cron)

  Manage software installation and updates

  Control services and daemons

Is There a Need for fork() in Python?

It all depends.

✅ When is fork() useful?

Building daemon processes or custom process managers
Implementing low-level concurrency or parallelism
Creating sandboxed subprocesses for isolation
Mimicking shell-like behavior (e.g., launching background jobs)

🚫 When is it better to avoid the use of fork()?

For most Python workflows, especially portable scripting, fork() is overkill. Use subprocess.run() or multiprocessing.Process() instead. They’re safer, cross-platform, and more Pythonic.

To run an external command : 	subprocess.run()

To spawn parallel Python code	:   multiprocessing.Process()

For background task/thread :  threading.Thread()

For async I/O :  asyncio

There is a distinction between shell variables and environment variables (for a shell).

# Shell variables, Scheme-variables and C-global-variables are basically the same idea.

To examine shell variables : set -o posix ; set

To examine environment variables : env

e.g.,
  > set -o posix ; set | less
  > set -o posix ; set | grep HOME
  > env | less
  > env | grep PWD

When a shell variable has been designated as an environment variable, this shell/environment variable will be "exported" as one of the environment variables of the process that is run by the current process or one of its descendent processes.

# to run a user "command", bash uses 'system()' or one of : execl(), execlp(), execle(), execv(), execve(), execvp(), and execvpe().

In other words, any UNIX/Linux process P will have a collection of environment variables to start with, and this collection of environment variables of P is a copy of the collection of environment variables of the parent process of P.

In addition to checking the values of shell/environment variables, bash provides supports for

  checking if the shell variable varname is set (has been assigned a value)
  checking if the shell variable varname is set and is a name reference

Also on the side (How should we view an environment function? What is its role???)

An environment function is a "shell script template". When an environment function is run (perhaps with positional parameters), the content of the environment function (which is a bunch of command lines, with all positional parameters replaced by the corresponding actual parameters) is run directly BY THE CURRENT SHELL. It is very likely that the system (the current shell) just replaces the call of an environment function with its (properly filled) content and then uses the DOT command to execute this replaced content.

Copilot :

To write a Python script that scans .cpp files for potential shellcode on Ubuntu 22.04, you'll want to combine file system traversal with pattern matching. Here's a breakdown of how to approach it:

1. Directory Traversal

Use os.walk() or pathlib.Path.rglob() to recursively find all .cpp files.

2. Shellcode Detection Heuristics

Shellcode in C++ files often appears as:

  Hex byte arrays (e.g. "\x90\x90\xeb\xfe")

  Inline assembly (__asm__, asm)

  Suspicious function calls (VirtualAlloc, memcpy, CreateThread, etc.)

  Obfuscated strings or encoded payloads

You can use regular expressions to detect these patterns.

3. Reporting

Log findings per file with line numbers and matched content.

import re
from pathlib import Path

# Define suspicious patterns
SHELLCODE_PATTERNS = [
    re.compile( r'\\x[0-9a-fA-F]{2}' ),  # Hex byte strings
    re.compile( r'__asm__|asm' ),        # Inline assembly
    re.compile( r'(VirtualAlloc|CreateThread|memcpy|LoadLibrary|GetProcAddress)' ),  
                                                                       # Common shellcode APIs
    re.compile( r'char\s+\w+\s*\[\s*\]\s*=\s*".*\\x[0-9a-fA-F]{2}' ),  # Byte arrays
]

def scan_cpp_files( directory: Path ) :
  
  for file_path in directory.rglob("*.cpp") :
      try :
        with file_path.open("r", encoding="utf-8", errors="ignore") as f :
          for lineno, line in enumerate(f, start=1) :
            for pattern in SHELLCODE_PATTERNS :
              if pattern.search(line) :
                 print( f"[!] Suspicious pattern in {file_path} at line {lineno}: {line.strip()}" )
      except Exception as e :
        print( f"[ERROR] Could not read {file_path}: {e}" )

if __name__ == "__main__":
  
  import sys
  
  if len(sys.argv) != 2 :
    print( "Usage: python detect_shellcode.py /path/to/scan" )
    
  else : # len( sys.argv ) == 2
    scan_cpp_files( Path( sys.argv[1] ) )

# include <iostream>
# include <filesystem>
# include <fstream>
# include <regex>
# include <string>

namespace fs = std::filesystem ;

const std::vector<std::regex> shellcode_patterns = {

    std::regex( R"(\\x[0-9a-fA-F]{2})" ),                      // Hex byte strings
    std::regex( R"(\b(__asm__|asm)\b)" ),                      // Inline assembly
    std::regex( R"(\b(VirtualAlloc|CreateThread|memcpy|LoadLibrary|GetProcAddress)\b)" ), 
                                                             // Common shellcode APIs
    std::regex( R"(char\s+\w+\s*\[\s*\]\s*=\s*".*\\x[0-9a-fA-F]{2})" ) // Byte arrays
} ;

void scan_file(const fs::path& file_path) {
  
  std::ifstream file(file_path);
  
  if ( ! file.is_open() ) {
    std::cerr << "[ERROR] Could not open: " << file_path << "\n";
    return;
  }
  
  std::string line ;
  int lineno = 0 ;
  while ( std::getline(file, line) ) {

    ++lineno;

    for ( const auto& pattern : shellcode_patterns ) {

      if (std::regex_search(line, pattern)) {
        std::cout << "[!] Suspicious pattern in " << file_path
                  << " at line " << lineno << ": " << line << "\n";
      }
    }
  }
}

void scan_directory(const fs::path& root) {
  
  if (!fs::exists(root) || !fs::is_directory(root)) {
    std::cerr << "[ERROR] Invalid directory: " << root << "\n";
    return;
  }
  
  for (const auto& entry : fs::recursive_directory_iterator(root)) {
    if (entry.is_regular_file() && entry.path().extension() == ".cpp") {
      scan_file(entry.path());
    }
  }
}

int main(int argc, char* argv[]) {
  
  if (argc != 2) {
    std::cerr << "Usage: ./detect_shellcode /path/to/scan\n";
    return 1;
  }
  
  fs::path target_dir(argv[1]);
  scan_directory(target_dir);
  return 0;
}

#!/bin/bash

# Directory to scan
TARGET_DIR="$1"

# Check input
if [[ -z "$TARGET_DIR" ]]; then
  echo "Usage: $0 /path/to/scan"
  exit 1
fi

# Define suspicious patterns
PATTERNS=(
  '\\x[0-9a-fA-F]{2}'                         # Hex byte strings
  '__asm__|asm'                               # Inline assembly
  'VirtualAlloc|CreateThread|memcpy|LoadLibrary|GetProcAddress'  # Common APIs
  'char[[:space:]]+[a-zA-Z_][a-zA-Z0-9_]*[[:space:]]*\[[^]]*\][[:space:]]*=[[:space:]]*".*\\x[0-9a-fA-F]{2}' # Byte arrays
)

# Scan .cpp files recursively
find "$TARGET_DIR" -type f -name "*.cpp" | while read -r file; do
  for pattern in "${PATTERNS[@]}"; do
    grep -En "$pattern" "$file" 2>/dev/null | while read -r match; do
      echo "[!] Match in $file: $match"
    done
  done
done
