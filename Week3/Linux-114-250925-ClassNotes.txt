# "A command is an executable, essentially."

1. 『Linux指令』的長相(the look of a Linux "command")

『Linux指令』的第一種長相：

  <a path leading to an executable> <argument 1> <argument 2> ...      # "請執行這個檔案！"
  # the given path cannot be just 'abc' (a name)

『Linux指令』的第二種長相：

  <name of an executable> <argument 1> <argument 2> ...                # "請找到這個檔案、然後執行它！"

Q : What does the system (bash) do when the user gives 第二種長相的command (such as the example below)?

e.g.,

> ssh -p 2222 wang@192.168.50.45
# 第二種長相  # 注意： =====> -p 2222 <===== 是兩個arguments，二者合起來表達『某個option的設定』
 
> /usr/bin/ssh -p 2222 wang@192.168.50.45
# 第一種長相

# 假設 
# > ls

2. When you log in to Linux by executing 'ssh' or just open a Terminal on the desktop,
   you will interact with 'bash'. (i.e., 'bash' is the program that is run, and it interacts with you)
   # well, bash or csh or ksh or sh or ... 通稱為shell (program)

The main() of 'bash' is something like the following : 
# This main() is supposedly almost the same as the main() of the PL project you wrote or will write.

  # define NOT !
  gUserWantsToQuit = false ;
  char * gUserInput = NULL ;
  char * gResponse = NULL ;

  while ( NOT gUserWantsToQuit ) {

    printf( "> " ) ;

    GetUserInput( gUserInput ) ;    # until user enters '\n' (but not "\\\n" or "\\ \n" or ...)

    ProcessUserInput( gUserInput, gResponse, gUserWantsToQuit ) ;

    if ( NOT gUserWantsToQuit )
      print( "%s\n", gResponse ) ;
    else // gUserWantsToQuit
      ;  // do nothing (just end this interaction)

  } // while NOT gUserWantsToQuit

重點：

  不管是第一種長相的command、還是第二種長相的command，二者都(只)是char string，(說穿了，一個command只是個string)
  而ProcessUserInput()的責任是(1)找到那個執行檔、(2)執行那個執行檔。

  同時，ProcessUserInput()在執行那個執行檔時、還必須把<argument 1> <argument 2> ..."傳"給那個執行檔！

  (當然、更別提還要有someone who performs a simple parsing of the user input string ...)

而這意味著：

  任何執行檔(就以『用C程式所產生的執行檔』為例)在執行時、必須要能接受『執行者』在執行此執行檔時所"傳"進來的(字串)參數。

觀念：

  『執行』一個執行檔 ＝ 『呼叫』一個function

觀念：

  A shell script is 『a program that works on the shell level』. 
  One very important basic instruction of a shell script is 『running an executable』.
  # C/C++ function 呼叫 functions (呼叫時傳(各種不同型別的)參數) ; script "呼叫" 執行檔 ("呼叫"時傳(字串)參數)
  Therefore, it should be fair to say that a shell script is, in effect, a "program of programs." 
  # "King of kings"

The main() of a C/C++ program can be written as :

int main() {
  ...
} // main()

But it can also be written as :

int main( int argc, char** argv ) {
  ...
} // main()

where 'argc' means "argument count" and 'argv' (argument values) is an array of strings (the arguments).
# and the argument(-string)s are : argv[0], argv[1], argv[2], ..., argv[ argc - 1 ]

Why PrintPara?

We know what an executable expects of the parameters that it receives when this executable is "called".

However, we may not be giving it the right parameters when we "call" this executable on the shell-level.

(We think we are giving it this and that char-strings as parameters. But actually, it may be 
 receiving string-parameters that are somewhat different from the strings we expect them to be.)

Therefore, we use this custom-made command 'PrintPara' to see whether the parameters we "give" 
to an executable are indeed the strings we intend to give to this executable.

We will be using PrintPara from time to time from now on.
